Real bugs this suite has caught
  • CI never ran the DB-backed suite, and a bare install never applied the module's schema either — two independent gaps, both fixed.
  • Tool schemas used camelCase inputSchema instead of Anthropic's snake_case wire format — silently harmless only because the affected tools took no arguments; confirmed and fixed against the real API.
  • json_decode collapsed an empty JSON object into an empty array, which the real Anthropic API rejected with a 400 once the key-name bug above was fixed.
  • The exception path never called the Langfuse tracer — a failing request produced no trace at all, invisible on the dashboard even though the error log recorded it correctly.
  • /readyz fell through to HTTP 200 with the exception message echoed into the body — both a readiness-signal bug and an information-leak violation. Fixed fail-closed.
  • 48% of this fork's own seeded active-problem rows (2,943 of 6,126) carry an onset date over 20 years old with no resolution date, still marked active — a real data-quality finding from a live query, not a synthetic fixture.

Key metrics

What "success" means for this agent's target user — KEY_METRICS.md. Four of six primary metrics are measurable today; the other two are named honestly as blocked or not-yet-instrumented rather than hidden.

1 · Claim-Grounding Rate Measurable
% of claims passing source-attribution check. Target 99%+.
Measured via the verification layer's pass/fail log.
2 · Verified Incident Rate Blocked
Clinician-flagged errors per 1,000 conversations. Target zero-tolerance.
Needs the "flag this answer" button — not yet built.
3 · p95 Time-to-Answer Measurable
95th-percentile latency, single-tool vs multi-tool. "Seconds not minutes."
Measured via Langfuse tracing.
4 · Audit Completeness Rate Measurable
% of conversations with a fully populated audit-log row. Target 100%.
Measured via count query on clinical_copilot_log.
5 · Adoption Rate per Eligible Visit No data yet
% of visits where the co-pilot was actually opened and used.
Instrumentable now — no value until real clinician usage exists.
6 · Cross-Patient Access Integrity Measurable
Tool invocations where audit patient id ≠ session patient id. Target 0 always — security canary.
No new instrumentation needed.
Secondary metrics (operational health)
Tool failure rate — DB/query health signal, not a trust signal.
Cost per conversation — $0.076/question average (range $0.035–$0.11), see Cost below.
p95/p99 latency under 10 and 50 concurrent users — infrastructure capacity, see Cost below.

Alerts

Three alerts on top of the Langfuse dashboard — ALERTS.md. Thresholds are derived from PERFORMANCE_BASELINE.md's measured numbers, not picked blind.

1 · p95 chat latency > 37s
Live
15-minute rolling window, root-span latency. Threshold = 2× the real-API smoke pass's measured p95 (18.5s).
On-call: Anthropic status page first, then instance CPU/memory saturation.
2 · Error rate > 5%
Not live
5-minute window, non-2xx ajax.php responses. Trace data now exists (traceFailure()); blocked purely by the connected Langfuse plan's 2-live-alert cap, not a data gap.
On-call: /meta/health/readyz first, then recent deploys, then Anthropic status.
3 · Tool failure rate > 2%
Live
15-minute window across the 4 chart-reading tools. Baseline observed 0 failures across ~800 mocked-load requests, so the threshold is a generous margin above that.
On-call: DB connectivity first, then schema-migration mismatch.
